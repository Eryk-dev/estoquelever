## Codebase Patterns
- Migration files go in `supabase/migrations/` with format `YYYYMMDD_description.sql`
- All tables prefixed with `siso_`
- Use `gen_random_uuid()` for UUID PKs
- Use `timestamptz NOT NULL DEFAULT now()` for created_at
- FK CASCADE only on child-item tables (itens → parent session)
- CHECK constraints for status enums directly in CREATE TABLE
- `tinyFetch` handles rate limiting via `runWithEmpresa` context — all new Tiny API functions must use it (not raw fetch)
- `buscarProdutoPorSku` pattern: `tinyFetch<{ itens: T[] }>` → return first item or null
- `getEstoque(token, produtoId)` returns `{ localizacao, depositos[] }` — use `localizacao` for product location and find deposit by `.id` for saldo
- For fire-and-forget processors: get token INSIDE the loop (not before) to handle expiry during long processing runs
- `runWithEmpresa(empresaId, fn)` wraps async scope for rate limiting — all tinyFetch calls within are automatically queued
- `atualizarLocalizacaoProduto` internally does GET+PUT (2 API calls) — fetches descricao+sku then updates location
- `getValidTokenByEmpresa(empresaId)` returns `{ token, connectionId }` — destructure `.token` before passing to API functions
- Supabase `select("id", { count: "exact", head: true })` returns `.count` for efficient counting without fetching rows
- `ilike("sku", value)` for case-insensitive SKU comparison (duplicate detection)
- Next.js 16 dynamic route params: `{ params }: { params: Promise<{ id: string }> }` — must `await params`
- Creator-only mutation pattern: `inventario.usuario_id !== session.id && !isAdmin` → 403
- Resolve deposito_id: `siso_tiny_connections WHERE empresa_id AND ativo=true` → `.maybeSingle()`
- Pill toggle button pattern: `cn("rounded-md px-3 py-1.5 text-xs font-medium", active ? "bg-ink text-paper shadow-sm" : "bg-zinc-100 text-ink-muted")`
- Form input pattern: `rounded-lg border border-line bg-surface px-3 py-2 text-sm text-ink outline-none`
- `useAuth()` provides `activeGalpaoId` for galpao-scoped client-side filtering
- Supabase disambiguated FK joins: `alias:table!fk_column(fields)` when a table has multiple FKs to the same target (e.g., `galpao_origem:siso_galpoes!galpao_origem_id(nome)`)
- useQuery conditional polling: `refetchInterval: (query) => { const s = query.state.data?.status; return s === "x" ? 2000 : false; }`
- Supabase OR filter for multi-FK galpao: `.or("galpao_origem_id.eq.${id},galpao_destino_id.eq.${id}")` — used when user should see rows where their galpao matches either side
