## Codebase Patterns
- Agrupamento atomic claim: `siso_claim_pedidos_para_agrupamento` RPC sets `agrupamento_expedicao_id='pending'` atomically. Only rows with `agrupamento_expedicao_id IS NULL` are claimed. Always call `recuperarPendingTravados` before claiming to unstick stale pending rows (>5 min).
- NF persistence gate: `nota_fiscal_id` + `chave_acesso_nf` must both be non-null before creating agrupamento. NF may exist before chave_acesso (SEFAZ authorization is async).
- Fire-and-forget pattern: agrupamento/etiqueta functions log errors but never throw. Callers don't need try/catch around them.
- Tiny API posture: `concluirAgrupamento` is non-fatal (Mercado Envios may return 400). Always attempt it but don't block on failure.
- On agrupamento failure: clear `agrupamento_expedicao_id` and `expedicao_id` back to null (matching `eq("agrupamento_expedicao_id", "pending")` guard) so the pedido remains eligible for retry.
- `processarPedido` (existing) does fase-1 + fase-2 (etiqueta). `criarAgrupamentoFase1` does only fase-1 (no etiqueta/ZPL).
- Separado orchestration: any endpoint that transitions pedidos to `separado` must call BOTH `preCriarAgrupamentosEmLote` (fallback create) and `recarregarEtiquetasFaltantes` (fast path label). Four current callers: concluir, concluir-oc, retry-etiqueta, compras-embalagem.
- Worker failure isolation: agrupamento calls happen AFTER stock is persisted. Since `criarAgrupamentoFase1` is fire-and-forget, agrupamento failure never causes job retry after `estoque_lancado`/`estoque_saida_lancada` are set.
- `enriquecerDadosNf` only transitions `aguardando_nf → aguardando_separacao` — safe to call from flows where status isn't `aguardando_nf` yet (e.g., OC before compra resolution).
- `gerarNotaFiscalPedido` is idempotent: returns existing `nota_fiscal_id` if set, or generates new NF. Ciclo 2 workers naturally detect existing NFs.
- Encaminhar reroute contract: NF fields are preserved (omission-based — not in update payload), shipping artifacts (agrupamento_expedicao_id, expedicao_id, etiqueta_*) are explicitly cleared. Any new field added to the reset must respect this split.
