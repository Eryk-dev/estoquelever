## Codebase Patterns
- `kickWorker()` from `execution-worker.ts` is the preferred way to trigger the worker (fire-and-forget with `.catch()`)
- `imprimirEtiquetaDireta()` is fast path (pre-claimed ZPL), `buscarEImprimirEtiqueta()` is slow fallback
- `registrarEvento()` from `historico-service.ts` is fire-and-forget safe — always `.catch(() => {})`
- EventoPedido type in `historico-service.ts` must be updated when adding new event types
- Optimistic lock pattern for atomic increments: `UPDATE ... WHERE quantidade_bipada = previous_value`
- Supabase `.not("field", "in", "(val1,val2)")` uses parenthesized comma-separated string (no spaces)
- `concluir-oc/route.ts` is the reference for OC resolution logic (decisao, galpao, execution queue)
- `SeparacaoPedido` field for order number is `numero_pedido` (not `numero`)
- API docs in `docs/api-reference-complete.md` must be updated for any new/changed endpoint
- Action bars per tab in separacao/page.tsx use IIFE pattern `(() => { ... })()` for computed local vars before JSX
- Inline mode UIs replace normal tab content via ternary in the `{/* Tab content */}` section of separacao/page.tsx
- `SeparacaoPedido` type has `nf_emitida`, `agrupamento_criado`, `etiqueta_pronta` booleans from GET /api/separacao
